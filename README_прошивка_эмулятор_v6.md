# SO-101 Leader Arm — эмулятор STS3215 на Arduino Nano

Инструкция по прошивке `прошивка_эмулятор_6.ino`: сборка, первая прошивка,
калибровка, повседневный запуск и разбор всех известных нюансов, из-за
которых это всё вообще пришлось чинить.

---

## 1. Что это вообще такое

Прошивка превращает Arduino Nano + мультиплексор PCA9548A/TCA9548A + 6×
энкодер AS5600 в устройство, которое по USB-Serial выглядит для хоста
(LeRobot / LeLab / MakerMods Lab / bambot) как шина из 6 настоящих
сервоприводов FeeTech STS3215 (ID 1–6, `model_number = 777`). Каждый
энкодер физически стоит на своём суставе leader-руки; прошивка читает
угол, пересчитывает его в формат регистра `Present_Position` протокола
STS3215 и отвечает на запросы хоста так, будто это реальный сервопривод
без торка.

---

## 2. Аппаратная часть

| Компонент | Назначение |
|---|---|
| Arduino Nano (или клон) | основной контроллер |
| PCA9548A/TCA9548A (адрес `0x70`) | I2C-мультиплексор на 8 каналов, по одному каналу на сустав |
| 6× AS5600 (адрес `0x36` на каждом канале мультиплексора) | магнитные энкодеры углов суставов |
| Подтяжки на A4/A5 (SDA/SCL) | обязательны для стабильной работы I2C |
| Конденсатор 10 мкФ между RESET и GND | подавляет автосброс платы при открытии COM-порта (см. §4) |

### Важно про конденсатор

Электролитический, **полярность важна**: длинная ножка (+) → на `RESET`,
короткая ножка со полоской (−) → на `GND`. Ставить **съёмным**
(проводки с крокодилами/разъёмом), не напрямую — см. §5 про перепрошивку.

---

## 3. Зачем вообще нужен конденсатор

Когда компьютер открывает COM-порт, он дёргает линию **DTR**, которая на
Arduino Nano напрямую сбрасывает чип (это штатный механизм, которым
пользуется Arduino IDE при заливке скетча). После сброса контроллер не
сразу начинает работать: около секунды крутится загрузчик (bootloader),
ожидая, не начнут ли заливать новую прошивку, и только потом стартует сам
скетч.

Настоящий сервопривод STS3215 никогда не перезагружается при
подключении — поэтому LeRobot и не закладывает время на ожидание такого
сброса. Он открывает порт и сразу начинает опрашивать моторы, а плата в
этот момент ещё может сидеть в загрузчике и молчать — отсюда падения типа
`Motor 'X' was not found` или полный краш подключения через 1–3 секунды.

Конденсатор гасит короткий импульс DTR, не давая напряжению на RESET
просесть настолько, чтобы чип реально перезагрузился — при этом обычная
кнопка reset (долгое, «настоящее» замыкание) продолжает работать как
обычно.

---

## 4. Первая заливка прошивки / переприветствование

1. **Отключить (выдернуть) конденсатор** — иначе автосброс, нужный
   Arduino IDE для входа в загрузчик, будет подавлен, и заливка не
   пройдёт.
2. Залить `прошивка_эмулятор_6.ino` через Arduino IDE как обычно.
3. Подключить конденсатор обратно (соблюдая полярность).
4. Проверить связь скриптом `ping_all.py` (см. §6) — все 6 ID должны
   отвечать сразу, без задержек.

Этот порядок нужен **каждый раз**, когда заливаешь новую версию
прошивки.

## 5. Калибровка — ДВЕ РАЗНЫЕ калибровки, не путать

Это самый частый источник путаницы, поэтому разберём подробно.

### 5.1 Калибровка нуля на уровне прошивки (register `0x50`)

Кнопки калибровки на плате больше нет (раньше была на A0 — убрана,
подробности в §7.2). Вместо неё — кастомный регистр `0x50` (в реальном
протоколе STS3215 не существует, поэтому безопасно переиспользован):
запись любого байта в этот регистр для конкретного ID обнуляет
калибровку так, что **текущее** сырое положение сустава становится
значением **2048** (середина шкалы 0–4095).

**Процедура (обязательно после каждой перепрошивки и при любых
подозрениях на разъезд нуля):**

1. Для каждого сустава по очереди (ID 1–6):
   - Руками поставь сустав **в середину его физического хода** —
     не в край, не в произвольное положение.
   - Запусти:
     ```
     python calibrate_zero.py /dev/ttyUSB0 <ID>
     ```
   - Убедись, что в ответ пришёл корректный ACK вида
     `ff ff <ID> 02 00 <checksum>`.

**Почему именно середина, а не край хода:** середина хода мапится на
2048 — у сустава остаётся ~2048 отсчётов запаса в обе стороны до границы
шкалы 4095↔0. Реальный ход сустава руки-манипулятора обычно меньше
этого запаса, так что граница шкалы никогда не оказывается внутри
рабочего диапазона движения — а именно попадание границы внутрь
диапазона вызывало резкие "прыжки на другую ось" и ошибку `Motor
discontinuity detected` при калибровке LeRobot (более ранняя версия
прошивки зануляла на краю хода — это было ошибкой, см. §7.6).

### 5.2 Программная калибровка LeRobot/LeLab/bambot

Это отдельный шаг **поверх** калибровки нуля из §5.1. LeRobot после
подключения попросит провести калибровку через интерфейс: начать с
серединной позы (все суставы по середине хода — та же поза, что и в
§5.1) и затем провести каждый сустав через полный диапазон хода. Так
записываются реальные пределы (`min`/`max`) для нормализации углов в
интерфейсе/3D-модели.

Если она падает с `Motor discontinuity detected` — значит калибровка
нуля из §5.1 либо не проводилась, либо проводилась в неправильной позе
(на краю, а не в середине). Переделай §5.1 и повтори.

## 6. Проверочные скрипты

Два python-скрипта (`pip install pyserial`), которые проверяют связь в
обход makermodslab/bambot — полезны для диагностики "плата не отвечает"
до того, как разбираться в самом приложении.

- **`ping_all.py <порт>`** — шлёт PING всем ID 1–6, печатает, кто
  ответил. Специально ждёт 2 секунды после открытия порта (переживает
  автосброс, если конденсатор ещё не стоит или не помог). Быстрый
  способ отличить "плата совсем не отвечает" от "проблема выше уровня
  прошивки" (порт занят другим процессом, браузер/приложение).

- **`calibrate_zero.py <порт> <ID>`** — калибровка одного сустава,
  см. §5.1.

Если `ping_all.py` не получает ответа вообще ни от одного ID — проверяй
в таком порядке: физическое питание/кабель → `sudo lsof /dev/ttyUSB0`
(не держит ли порт другой процесс) → конденсатор и полярность → сама
прошивка залита корректно.

## 7. Разбор нюансов и почему они возникли

Список всех проблем, с которыми уже столкнулись, и что каждая из них на
самом деле означает — на случай похожих симптомов в будущем.

### 7.1 Полная тишина на 115200 бод
Прошивка использует `Serial.begin(1000000)` — сборки на 115200 давали
полную тишину. Используй именно 1,000,000 бод во всех инструментах,
которые обращаются к плате напрямую.

### 7.2 Кнопка калибровки на A0 (убрана)
Раньше кнопка на A0 (`INPUT_PULLUP`, физически не подключена) при каждом
автосбросе платы могла случайно читаться как "нажата" из-за наводки на
висящий в воздухе вход, уводя плату в 2-секундное блокирующее ожидание
подтверждения — то есть Serial молчал ровно тогда, когда хост уже
пытался достучаться. Убрана полностью, калибровка теперь через регистр
`0x50` (см. §5.1).

### 7.3 Автосброс по DTR (конденсатор)
См. §3. Тот же класс проблемы, что и с кнопкой (тишина платы в момент
хендшейка), только на уровне самого Arduino-бутлоадера, а не нашего
кода — поэтому решается аппаратно, не прошивкой.

### 7.4 Джиттер ~0.1° на неподвижной руке
Собственный шум AS5600: сырое значение регистра ANGLE "гуляет" на ±1
младший бит (12 бит на 360° → 1 LSB = 0.088°) даже при полной
неподвижности. Прошивка сглаживает это экспоненциальным фильтром
(alpha=1/4) прямо в цикле опроса датчиков, с корректной обработкой
перехода через границу 0/4095. Если после калибровки фильтр покажется
слишком "вязким" при быстром движении — можно ослабить, поменяв
`diff / 4` на `diff / 2` (быстрее реакция, меньше сглаживание) в
функции опроса датчиков.

### 7.5 Мультиплексор — защита от кросс-тока между суставами
`selectI2CChannel()` теперь проверяет обратным чтением регистра
мультиплексора, что канал реально переключился, прежде чем читать
AS5600. Раньше, если селект канала сбивался (наводка/вибрация при
движении), следующее чтение AS5600 могло молча вернуть данные с
**чужого** канала без ошибки I2C — это и давало ощущение "двигаю один
сустав, а скачет другой". Если селект не подтвердился — замер просто
пропускается (старое значение сохраняется), а не подставляется
ошибочное.

### 7.6 Discontinuity при калибровке LeRobot
См. подробности в §5.1 — калибровка нуля должна проводиться **в
середине** хода сустава, не на краю. Ранняя версия инструкции (калибровка
на краю) была ошибочной именно из-за этого.

### 7.7 Челюсть/гриппер не двигается, хотя значение в интерфейсе меняется
Единственная проблема из всего списка, которая **не решается
прошивкой** — вероятная причина механическая (магнит/вал энкодера
челюсти проскальзывает относительно самой челюсти) либо в диапазоне
калибровки LeRobot для этого сустава (если во время программной
калибровки §5.2 челюсть не была доведена до упора в обе стороны).
Проверка: покрути вал энкодера челюсти рукой (по возможности отдельно
от механизма) и посмотри, растут ли сырые градусы линейно на всём
диапазоне. Если да — переснять калибровку LeRobot для этого сустава,
доводя челюсть до обоих упоров. Если нет — механическая расстыковка.

## 8. Быстрый чек-лист "после любой перепрошивки"

1. Выдернуть конденсатор → залить прошивку → вставить конденсатор обратно.
2. `python ping_all.py /dev/ttyUSB0` — все 6 ID отвечают сразу.
3. Каждый сустав в середину хода → `calibrate_zero.py` для ID 1–6.
4. Подключиться в makermodslab/bambot, убедиться что находит все 6 моторов.
5. Пройти калибровку LeRobot/bambot (серединная поза → полный диапазон
   хода на каждый сустав).
6. Ручная проверка: нет джиттера в покое, нет скачков на другую ось,
   челюсть двигается синхронно со значением.
